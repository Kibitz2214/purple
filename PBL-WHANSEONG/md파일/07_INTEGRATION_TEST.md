# 07. 통합 테스트

- 브랜치: `dev`
- 선행 조건: `feat/analysis`, `feat/recommendation` 모두 `dev`에 머지 완료
- 완료 후: `08_USABILITY_TEST`로 진행

## 목적
분석 묶음(02~03)과 추천 묶음(04~06)이 합쳐진 `dev` 기준으로,
전체 시나리오가 끊김 없이 동작하는지 검증한다.

## 테스트 시나리오
1. 학번 로그인 → 마이페이지에서 이수 현황 확인
2. 부족 카테고리 확인 → 추천 목록 노출 확인
3. 추천 과목 "바로 신청" → 수강신청 반영 (정원/시간표 충돌 검증 포함)
4. 신청 후 마이페이지 재조회 → 이수 현황이 갱신되어 부족 학점이 줄어드는지 확인
5. 신청 과목에 강의평가 등록 → 평점이 추천 정렬에 반영되는지 확인 (`06_REVIEW_ENHANCE`)
6. 졸업요건을 모두 충족한 학생 케이스 → 추천 목록이 정상적으로 비어있는지 확인
7. 학과/입학년도별 `GraduationRequirement`가 없는 예외 케이스 처리 확인

## 작업 항목
- [ ] 시나리오별 수동/자동 테스트 체크리스트 작성
- [ ] 발견된 결함 이슈로 기록 (담당 묶음 표시)
- [ ] 회귀 확인: 기존 기능(검색/필터/정렬/시간표 충돌/강의평가 CRUD) 영향 없는지 확인

## 완료 조건 (Definition of Done)
- 위 시나리오 전부 정상 동작
- 발견된 결함이 없거나, 모두 이슈로 등록되어 추적 가능한 상태
